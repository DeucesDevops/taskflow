# Verification evidence

Keep existing historical notes in ../verification.md. Store new dated implementation evidence here; folder creation alone does not prove a running environment.

Use YYYY-MM-DD-<environment>-<stage>.md. Record the source revision, environment, operator, executed checks, expected and observed outcomes, failures or limitations, sanitized evidence references and cleanup performed.

Do not store credentials, populated environment files, kubeconfigs, Terraform state or secret-bearing command output.

See [the implementation exit conditions](../plans/implementation-plan.md).
